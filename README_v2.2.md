# KYUTECH GROWTH Ver.2.2 — クラウド入力テスト

**架空データ専用。実在の選手や身体測定値は入力しないでください。**

## 目的

Ver.2.1のSupabase Auth・閲覧画面を維持し、以下の3つのクラウド入力を試します。

| 役割 | 新規機能 | 位置 |
|---|---|---|
| 選手 | 月ごとの短期目標の作成／テキスト編集 | 目標 |
| 選手 | 練習記録の新規保存 | 練習 |
| 監督・スタッフ | 測定値1項目の新規登録と監査記録 | 成長・測定 |
| 保護者 | 入力機能なし（閲覧専用） | — |

## 配布前のSQL（必須）

Supabaseの **kyutech-growth-dev → SQL Editor** で `13_cloud_write_measurement_rpc.sql` を実行し、続けて `14_verify_cloud_write.sql` で確認してください。

前提：これまでのSQL（25テーブル、04 目標RLS、06 練習RLS、09 通知表RLS、12 ログイン権限）が成功していること。

13のSQLは既存データを削除せず、監督／スタッフの所属をDB側で検証して新しい測定セッションと値と監査ログを**同じトランザクション**で作成するRPCを追加します。一般ユーザーには測定テーブルの直接書き込みを許可しません。再実行しても測定結果を増やしません。

## GitHub Pagesへの公開

1. 現在のVer.2.1リポジトリをバックアップします。
2. このZIPを解凍し、フォルダの中身をリポジトリの最上位へアップロードします。ZIPそのものをアップロードしません。
3. ファイルを分割してアップロードする場合は全ファイルのCommit完了後に動作確認します。
4. `index.html`、`cloud-app.js`、`cloud-app.css`、`sw.js` がv2.2に更新されているか確認します。
5. GitHub Pagesの `https://kotaro-hori.github.io/kyutech-growth-pwa/` を開きます。
6. 古い画面が表示されたらオンラインでリロードし、必要に応じてPWAのキャッシュを更新してください。IndexedDBやサイトデータの削除はしないでください。

## 4役割での実操作テスト

1. **選手**でログイン →「目標」で任意の来月の目標文を保存 → 一度ログアウトして再ログイン → 目標が表示される。
2. **選手**で「練習」→ 架空の記録を1件保存 → 再読み込み後も表示される。
3. **保護者**でログイン → 子どもの目標・練習記録が見える。入力フォームは表示されない。
4. **監督**でログイン →「成長・測定」→ テスト選手Bを選び50m走など1項目を新規保存 → 記録が表示される。
5. **スタッフ**でも別の架空測定を1件登録する。
6. **選手・保護者**でログイン → 測定入力フォームは表示されないことを確認する。
7. SQL Editorで `14_verify_cloud_write.sql` を再実行して登録者と監査ログが残っていることを確認する。

## セキュリティ・既知の制約

- **新規測定の入力と過去の測定の訂正は別機能**。Ver.2.2では訂正フォームは提供しません。
- 練習記録は新規作成のみ。タグ付け・既存記録の編集は次版以降です。
- 短期目標は同月既存レコードがあれば目標文のみ更新し、なければ新規登録します。
- 端末内デモのデータをクラウドへ転送しません。従来のデモは `demo.html` で確認できます。
- オフラインのクラウド入力は提供しません。通信エラー時は保存できないことがあります。
- UIのボタン非表示はセキュリティではありません。Supabase Auth + RLS + GRANT と検証済みの測定登録RPCが判断します。
- 今回の実機・別ユーザー直接API・権限改ざんテストは開発者環境で未実施です。実在の未成年者データ・InBody原本は投入しないでください。
- 公開GitHub Pagesには**Publishable keyのみ**使用。service_role、secret key、DBパスワードは絶対に含めません。
