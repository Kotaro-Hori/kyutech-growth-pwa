# KYUTECH GROWTH Ver.2.1 — 本体クラウド閲覧統合版

## 使い方
1. Ver.2.0のGitHubリポジトリをバックアップしてから、ZIPを解凍し中のファイルを**ルートへ上書きアップロード**する（ZIP自体ではない）。
2. https://kotaro-hori.github.io/kyutech-growth-pwa/ を開く。初回はSupabase Project URLとPublishable keyが必要な場合がある。Ver.2.0のcloud-test.htmlで接続設定済みなら同じブラウザで流用される。
3. 登録済みの4つのSupabaseテストアカウントでログインし、ホーム・選手・測定・目標・練習・通知表の表示件数を確認する。
4. ログアウトして別の役割をテストする。更新ボタンでSupabaseから再取得できる。

## 実装内容
- メイン `index.html` がSupabaseログイン・クラウド読み取りUIになった。役割別メニューとKYUTECH配色・アイコンを使用。
- `cloud-app.js` / `cloud-app.css` を追加。Authセッションは`cloud-test.html`と同じブラウザ認証キーを使用。
- 選手、測定、短期/長期/数値目標、練習記録/助言/処方、通知表をRLS範囲内で読み取り。
- **旧Ver.1.9のIndexedDBデモを `demo.html` に退避**。クラウドのデータを旧ローカルへコピーしない。旧デモの編集・保存はローカル専用。
- 新しいメイン画面はデータ登録・編集・削除・オフライン同期を行わない。ブラウザのアプリHTML/CSS/JSだけをService Workerでキャッシュし、Auth API結果はキャッシュしない。
- 既存のPWAローカルデータを意図的に削除しない。ただしUIの直接互換はなく、旧デモへのリンクから操作する。

## 必ず守ること
- 架空データのみ。実在する児童・生徒の個人情報、InBodyデータを入力しない。
- SupabaseのSecret / service_role / データベースパスワードをブラウザに入力しない。`sb_publishable_...`だけを使用する。
- クラウドの選手IDはUUID、ローカルのデモIDは文字列で**直接混ぜない**。
- ログイン可能であることと本番運用可能であることは異なる。RLSの負荷テスト、全書込権限、別家庭・別チーム、監査履歴改ざん防止、共有端末対策等が未検証。
- 以前のデモ画面は暗号化されていない端末内保存。`demo.html`でも実在データを使わない。

## テスト手順
- 監督・スタッフ：選手2名、測定2件、通知表2件が期待値。
- 選手・保護者：選手1名、測定1件、通知表1件が期待値。
- 練習・助言は以前の06 SQLを完了している場合に表示される。前の06 SQLが未実行の場合は取得エラーになる可能性がある。
- 読み取り失敗時は、エラーに表示されるテーブル名とPostgRESTのエラーコードを確認する。
- PWAが古い場合はオンラインで再読み込みする。Service Worker更新のため旧タブを閉じ再度開く場合がある。

## 構造
- index.html: クラウド版アプリ入口
- cloud-app.js/cloud-app.css: 新しい本体画面
- demo.html + app.js + local-db.js: 旧デモ（変更しない）
- cloud-test.html/cloud-test.js: Ver.2.0接続テスト画面
- sw.js: Ver.2.1専用キャッシュ
