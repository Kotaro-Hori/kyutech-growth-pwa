# KYUTECH GROWTH Ver.1.8 — 端末内データベース試作版

## 何を変更したか

Ver.1.7のUIと保存済み試作データ形式を維持し、IndexedDBの22種類のオブジェクトストアを追加しました。
* `app` ストア：従来のUIが読み書きする互換性スナップショット（そのまま残します）。
* 22ストア：保存時に`app`のデータを対応する表へ展開したもの。**IndexedDBのオブジェクトストアであり、SQLのリレーショナルテーブルではありません。**
* 既存の`writeState`に加え、全ストアを1つのIndexedDBトランザクションで保存。異常時にはトランザクション全体が取り消されます。
* スタッフ／監督の「データ入力 → 設定・バックアップ」にテーブル名と件数・先頭20件の確認機能を追加。
* IndexedDB のDB名は `kyutech-growth-prototype-v1` のまま、バージョンを2に更新。既存のデータはアップグレード時に削除しません。
* PWAのキャッシュ識別子をv1.8に更新。追加の `local-db.js` もオフライン対象に追加。

## 重要な制約（本番用ではありません）

1. **各画面は引き続き互換スナップショット `app/state` から読み込みます。** 22ストアはそのデータを構造化した**保存先の試作品**です。22ストアからUIを直接再構築する処理は未実装です。したがって、22ストアを外部から直接書き換えても画面には反映されません。
2. 22ストアは保存時に一度消してスナップショットから再生成します。**差分更新や目標の変更履歴の保持機能はまだありません。** たとえば短期目標は現行UIの「選手ごとに1つ」の保存形式を反映します。
3. 主キー・外部キー・CHECK制約はPostgreSQLのように自動で検証されません。現状のデモにはスタッフIDとコーチ名IDの違いなど、将来の正式DB移行で修正が必要な関連があります。
4. 野球成績とチャットのデータは、従来の互換スナップショットに残ります。**22ストアには分解しません**（今回の設計対象外）。
5. 監督の通知表は現行UIにある「野球・体づくり」の2評価をテーブルに展開します。項目の詳細追加と下書き・公開状態の切替は未実装です。
6. 正式なログイン、RLS、他アカウントからのデータ保護、クラウド同期はありません。**本物の選手・家庭・InBodyの情報を保存しないでください。**
7. PDF・写真は現行スナップショットと22ストアの両方に保存され得ます。容量に注意してください。
8. 保存領域はブラウザ、サイトURL、ホーム画面PWAの環境ごとに異なります。ブラウザデータ削除で記録が失われる場合があります。

## 保存処理を学ぶ場所

- `index.html`：`local-db.js` と `app.js` を読み込む。
- `local-db.js`：22ストアの定義、画面データから表形式に変換する `projection`、保存 `write`、閲覧 `counts` と `rows`。
- `app.js`：実際の画面、入力イベント、`persist`、`writeState`、読み込み `readState`。
- `sw.js`：オフラインで必要なファイルをキャッシュする。

## テスト例

1. `python -m http.server 8000` でローカル起動。
2. `staff01 / Staff123!` でログイン。
3. データ入力でテスト選手の測定値を入力して保存。
4. データ入力 → 設定・バックアップ → テーブル一覧の件数を確認。
5. `measurement_sessions` を選択して測定回を確認。
6. `measurement_values` を選択して各測定値を確認。
7. ページを再読み込みして成長メニューでも保存値を確認。
8. 別アカウント・別選手で他人のデータを隔離できるか試す。この版では**本物のアクセス制限がない**ことを理解する。
