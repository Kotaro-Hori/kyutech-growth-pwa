# KYUTECH GROWTH Ver.1.9｜クラウド移行・セキュリティ設計準備版

## この版で実装したこと
- Ver.1.8のデモUI・IndexedDB保存・22種類の保存領域を維持。
- ログイン画面に「架空データ専用」と安全性の注意を明示。
- スタッフ／監督「データ入力 → 設定・バックアップ」から安全確認ガイドへのリンクを追加。
- `security-guide.html` に運用判断・技術チェック項目を設置（チェックは保存しません）。
- `supabase/sql/01_schema_draft.sql` に22テーブルのSQL下書きを同梱。全テーブルでRLSを有効にし、`anon` / `authenticated` のアクセス権を取り消す**初期拒否構成**。利用者向けポリシーはまだありません。
- `ACCESS_MATRIX_V1.md` と `DECISIONS_V1.md` を同梱。
- PWAキャッシュ名・アセットのバージョンを1.9に更新。

## まだ実装していないもの
**Supabase Authの正式ログイン、RLSポリシー、クラウドデータ保存、端末間同期、Storageの権限は未実装。**
この版はセキュリティが完成したアプリではありません。実際の選手データやInBody値は登録しないでください。

## SQLの使用上の注意
SQLはレビュー用の設計ドラフトです。既存の本番・試験DBには適用せず、まず新しい空の開発プロジェクトで検証してください。`CREATE TABLE` / `RLS` / `REVOKE` により構造が生成されますが、アプリが接続できる状態にはなりません。SQLを実行しても自動的にアプリのセキュリティは向上しません。

## Windowsで試す
1. ZIPを解凍し、`index.html` のあるフォルダを開く。
2. アドレスバーに `cmd` → `python -m http.server 8000`。
3. `http://localhost:8000/` を開く。
4. ログインの注意表示、`security-guide.html` の表示、既存の架空測定データの保存と表示を確認する。
5. 必ずバックアップを取ってから既存GitHub Pagesを更新する。ファイル単位で最上位にアップロードし、`security-guide.html` も含める。

## Supabase導入に必要な次の作業
- 監督とアクセス範囲を決めて `ACCESS_MATRIX_V1.md` を確定。
- SQLドラフトのチーム所属・保護者紐づけの制約、RLSポリシー、権限付きアカウント発行処理を設計・テスト。
- 架空データでAuth + RLSの直接APIアクセス検査。
- 設定済みの安全なバックエンドにアプリのデータ保存処理を移行。
- ローカルデータのキャッシュ・バックアップ・復元・オフライン使用時のルールを追加検証。
- 最後に個人情報取扱いと実運用を審査。
