# KYUTECH GROWTH Ver.2.3 — 測定一括入力・訂正・練習記録編集

**架空データ専用。実在の児童・身体測定値・InBody原本を登録しないでください。**

## 変更点
- 監督・スタッフ：パフォーマンス測定項目を一括入力。同一日・同一区分の項目を1セッションに格納。空欄はスキップ。各項目の監査履歴を記録。
- 監督・スタッフ：既存測定値を選び、訂正理由を入力して訂正。既存の `correct_measurement_value` RPCを使用。
- 選手：自分の過去の練習記録を選択し、日付・内容・振り返りを編集。以前のRLS（本人のみUPDATE）を使用。
- 保存成功後は再取得・画面更新。クラウドと旧IndexedDBは混ぜない。
- Ver.2.2の単一項目登録RPCは残るが、Ver.2.3画面は一括登録RPCを使う。

## 実施順序
1. `kyutech-growth-dev` のSupabase SQL Editorで `15_measurement_batch_rpc.sql` を実行。
2. `16_verify_v23.sql` を実行し、3つの関数が存在することを確認。
3. 現行GitHubリポジトリと端末内デモデータをバックアップ。
4. ZIPを解凍し、**フォルダ内のファイル**をGitHub Pagesのリポジトリ最上位へアップロード。必須更新: `index.html`, `cloud-app.js`, `cloud-app.css`, `sw.js`。
5. GitHub Pagesでログインし、テスト選手のみで下記を確認。

## 動作確認
- 監督で「成長・測定」→ テスト選手B → 同じ測定日に **2つ以上**の架空測定値を入力 → 保存。画面で2項目が表示される。
- スタッフでも架空の測定値を入力。
- 監督で「登録済み測定値を訂正」→ 今追加した値を選択 → 別の値と理由を入力 → 保存。更新後の値が表示される。
- 選手で「練習」→ 「過去の練習記録を編集」→ 以前の記録を選び文章を変更 → 保存。保護者で更新内容を確認。
- `16_verify_v23.sql` で監査履歴を確認。複数INSERTとUPDATEを確認。
- 選手・保護者には測定入力・訂正フォームがないことを確認。フォームが隠れるだけでは権限検証にならないため、本番導入前に**直接APIでの拒否テスト**を実施。

## セキュリティと制約
- 一括登録はDB内でログインID・有効なチーム所属・監督/スタッフ権限を検証し、全項目・監査を1トランザクションで保存。
- 測定値の直接更新・挿入は禁止。訂正は既存の関数と監査処理に依存。
- 練習記録編集は既存の本人限定RLSに依存。Ver.2.3は練習記録編集の監査履歴を実装していない。
- オフライン入力・クラウド同期競合・移籍・退団などの本番仕様は未完成。
- JavaScript構文チェックは可能だが、利用者のSupabase上での実ブラウザ試験は未実施。
- `service_role`・Secret・パスワードはGitHubに置かないこと。
