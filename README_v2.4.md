# KYUTECH GROWTH Ver.2.4｜育成サイクル・編集監査（架空データ専用）

## Ver.2.3からの変更
- 選手は練習記録の新規登録・編集時に、自分の短期目標と紐づけできる（未指定も可）。
- 監督・スタッフは指導コメントを登録できる。本人・紐づく保護者・指導者は既存RLSに従って閲覧できる。
- 練習記録の**UPDATE**について、サーバー側トリガーが更新前後の内容・操作者・日時を `internal_audit.audit_events` に保存する。過去の編集履歴を遡って作成するものではない。
- 測定値の一括入力・訂正はVer.2.3のまま維持。

## 導入順序
1. **Ver.2.3のバックアップ**を確保。実在選手のデータは使用しない。
2. Supabase `kyutech-growth-dev` の SQL Editorで `17_v24_training_audit.sql` を実行。新しいSQL Editorで `18_verify_v24.sql` を実行。既存テーブルを削除しない。
3. ZIP内ファイルをGitHubリポジトリの**ルート直下**に上書き（ZIP自体や解凍したフォルダをアップロードしない）。コミット後 `https://kotaro-hori.github.io/kyutech-growth-pwa/` を開く。
4. 選手で短期目標を作成し、練習記録に関連づけて保存。編集してページ更新し、変化を確認。
5. 監督・スタッフで助言を入力、選手・保護者で見えることを確認。
6. SQL Editorで `18_verify_v24.sql` を再実行し、`training_logs` の UPDATE の監査履歴を見る。

## 注意
- `coaching_advice` の既存 RLS/GRANT（06番のSQL）が正常に導入されていることが前提。
- 新規データの登録や編集の監査が**全テーブルで実装済み**という意味ではない。練習記録は今回 UPDATE を対象とし、INSERT は監査対象外。
- コメントには実在の児童の個人情報や医療情報を書かない。
- オフライン同期・同時編集の競合制御・本番安全性評価は未対応。
- 1チームの試験専用。ブラウザからは `internal_audit` を直接読めない。
- 目標と助言の閲覧可否は Supabase 側の RLS に従う。クライアントのボタン表示だけで権限制御はしていない。
